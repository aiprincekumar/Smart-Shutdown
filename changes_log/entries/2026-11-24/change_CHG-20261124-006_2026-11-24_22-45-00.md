## 📋 1. Purpose & Architectural Rationale

Permanently eliminate the visual window flash of the Full Studio desktop window during `--mini-hud` / Windows boot startup, and compact `gui/unified_app.py` to maintain the strict Universal Rule 28 code modularity budget (431 lines):
1. **Immediate Pre-Construction Window Withdrawal (`gui/unified_app.py`):**
   - Relocated `self.withdraw()` to execute at the very top of `UnifiedSentinelApp.__init__` immediately after `super().__init__()` when `start_in_mini_hud=True`.
   - Prevented `_center_window()` from triggering `self.update_idletasks()` when starting in Mini HUD mode, completely preventing Tkinter from rendering the 780x520 master window to the screen before overlay creation.
   - Removed redundant secondary `self.withdraw()` call from the post-start hook.
2. **Dual-Timer Event Forwarding & State Synchronization (`gui/unified_app.py`):**
   - Restored and verified `idle_sec` and `idle_threshold` forwarding in `_handle_tick_event`, `_handle_state_change_event`, `_handle_telemetry_data_event`, and `update_countdown_display`.
   - Guaranteed full compliance with `test_battery_4_unified_app_dual_dispatch` across dual simultaneous timers (master shutdown countdown + physical user inactivity).
3. **Strict Line Budget Compaction (`gui/unified_app.py`):**
   - Streamlined imports and widget initializations to achieve exactly `431 lines` (well below the <= 450 line threshold of Rule 28).
4. **Hermetic Regression Test Coverage (`tests/test_mini_hud_startup_transition.py`):**
   - Added `test_window_withdrawn_immediately_before_ui_construction` verifying that `self.withdraw()` is called prior to `_center_window` and `_build_ui`, ensuring `wm_state() == "withdrawn"` before any widget drawing occurs.
   - Master test suite regression verified: 273/273 tests pass (100% PASS, 0 failures, exit code 0).
