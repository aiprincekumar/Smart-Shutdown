## 📋 1. Purpose & Architectural Rationale

Fix Mini HUD static/hardcoded status pills and strictly enforce Rule 28 line count budget in `gui/unified_app.py`:
1. **Dynamic AntiGravity AI Status Pill:**
   - Eliminated hardcoded `'Work' if 'COUNTDOWN' in st_name else 'Ready'` binding.
   - Bound Mini HUD AI badge dynamically to authoritative coordinator AI engine state (`self.coordinator.ai_state`):
     - `ready` / `idle` -> `✨ Ready`
     - `work` / `busy` -> `⚙️ Working`
     - `wait` / `input` -> `💬 Waiting`
2. **Dynamic Sentinel Status Pill (Single-Word Statuses):**
   - Eliminated static `'Run'` and replaced with dynamic single-word operational statuses:
     - `👤 Away` (when inactive countdown is running / `COUNTDOWN_ACTIVE`)
     - `💤 Idle` (when user active / `IDLE_MONITORING`)
     - `🚪 Closing` (when applications are being closed / `PRE_SHUTDOWN_GRACE`)
     - `⚡ Shutdown` (when shutdown is executing / `SHUTDOWN_EXECUTED`)
     - `⏸️ Paused` (when countdown is paused)
     - `🛑 Blocked` (when inhibitors/blockers detected)
3. **Precedence Fix for Application Grace:**
   - In both `TitleBarComponent` and `UnifiedSentinelApp`, prioritized `CLOSING`/`GRACE` before `SHUTDOWN` so that `PRE_SHUTDOWN_GRACE` correctly resolves to `🚪 Closing` instead of prematurely indicating `⚡ Shutdown`.
4. **Rule 28 Line Count Budget Compliance:**
   - Refactored `gui/unified_app.py` to 448 lines, strictly meeting the `<= 450` lines budget enforced by `test_rule28_line_count_budgets`.
5. **Tkinter Visual Isolation Safeguard:**
   - Identified Tkinter GUI window spawn issue causing white frozen desktop popups during automated test execution. Per user command, visual GUI tests are segregated for manual verification while non-visual core unit test suites (coordinator, sentinel, input_hook, app_closer, waiting_gate, history_view, logs_view, title_bar_cluster) are fully automated and verified.
