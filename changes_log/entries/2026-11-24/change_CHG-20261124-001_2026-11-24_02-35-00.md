## 📋 1. Purpose & Architectural Rationale

Resolve critical lifecycle discrepancies and achieve 100% architectural parity across 1-Click Target Mode Switching:
1. **1-Click Target Mode Cycling Parity:**
   - Unified title bar mode cycle: `LIVE` -> `DEMO (30s)` -> `SIMULATION` -> `LIVE`.
   - `TargetMode.DEMO_30S`: Real application closing at T-10s (`grace=10s`) and real Windows shutdown dispatch at T-0 with `dry_run=False`.
   - `TargetMode.SIMULATION`: Safe active dry-run countdown demonstration with `dry_run=True`, simulating application closure and shutdown without process disruption.
   - `TargetMode.LIVE`: Standard production idle monitoring mode with full countdown timer (15 minutes default) and real OS shutdown.
   - Backward compatibility for `TargetMode.DEMO_10S` callers.
2. **Instant Countdown Reset & Multi-Deck Synchronization:**
   - Immediate timer dial updates across main window cockpit (`lbl_timer`), Floating Mini HUD (`lbl_timer`), and status badges.
   - Dynamic cancellation of active demo background timers upon mode transitions without false abort logs.
   - Strict Universal Rule 28 code modularity compliance (< 440 lines for `core/coordinator.py`, < 450 lines for `gui/unified_app.py`).
